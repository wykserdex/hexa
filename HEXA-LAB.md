# HEXA Lab — работающий вертикальный прототип

Это экспериментальное продолжение HEXA: **наблюдение → намерение → планировщик → адаптер → подтверждение**.

**Подключён только локальный симулятор.** Здесь нет интеграции с обычными матчами Dota, чтения памяти игры, инъекций или эмуляции ввода. Способности, характеристики, цены действий, скорость и перемещение — условная модель, а не воспроизведение механик или баланса Dota. Исходный `carrier/` оставлен без изменений и этой демонстрацией не проверен.

## Запуск

Нужен Python 3.10+. Зависимостей у приложения нет.

```bash
python -m hexa lab
```

Открыть **http://127.0.0.1:8080** в браузере. Для размещения в среде с проксируемым preview:

```bash
python -m hexa lab --host 0.0.0.0 --port 8080
```

Сервер — инструмент локальной разработки. Не публикуйте его в интернете без аутентификации. **Один процесс обслуживает одну общую арену:** разные вкладки и пользователи управляют одним состоянием.

## Что попробовать первым

1. Открыть **Сценарии → Комбо против фарма → Запустить проверку**.
2. Увидеть, как фарм приостанавливается, четыре способности выполняются с разными временами, затем фарм возобновляется.
3. Запустить **Игрок важнее автоматики**: оставшиеся шаги действительно переходят в `cancelled`, а не просто скрываются из интерфейса.
4. В **Модулях** включить все четыре направления и изменить порог HP для автопредмета.
5. Сопоставить анимации полигона с **Журналом** и экспортом JSON.

### Управление

| Действие | Клавиша / элемент интерфейса |
|---|---|
| Комбо по выбранной цели | `Q` / «Запустить комбо» |
| Снизить HP героя до 28% | `H` / «Тестовый урон» |
| Перехватить управление на 4 игровых секунды | `Space` / «Перехватить» |
| Выбрать юнита | Клик по карте или кнопка в панели цели |
| Ручной приказ движения герою | Правая кнопка по карте |
| Остановить игровые часы | Пауза над картой |
| Сбросить состояние с сохранением настроек модулей | Кнопка сброса над картой |

Хоткеи обрабатываются **только внутри этой веб-страницы**, не глобально в системе. На телефоне используйте кнопки; правой кнопке мыши отдельного сенсорного аналога нет.

## Реально реализованные модули

- **Комбо, P60.** Четыре структурированных CAST-команды с отдельными сроками `0 / 0.60 / 1.25 / 1.95 с`. Резервирование героя, проверка маны/цели/дальности/перезарядки, отмена группы при отказе адаптера.
- **Автопредметы, P90.** Наблюдение за порогом HP, лечение на 420 HP, 14-секундная перезарядка. Экстренный предмет может сработать во время комбо.
- **Фарм, P10.** Выбор ближайшего живого нейтрала, подход на дистанцию атаки, атака. Перемещение прямолинейное: навигационной сетки в модели нет.
- **Микроконтроль, P20.** Независимые команды двум подконтрольным Искрам. Здоровый юнит идёт к противнику; при HP < 35% отступает к герою.
- **Информационные панели.** Здоровье, мана, готовность способностей/предмета, выбранная цель, владелец управления, очередь, метрики и реальные результаты команд.
- **Ручное управление, P100.** Остановка текущих автоматических приказов и отмена отложенных, включая оставшиеся шаги комбо.

Модули могут быть выключены; их очередь и текущие приказы тогда отменяются. Сбой планирующего модуля изолируется, записывается в журнал и отключает этот модуль.

## Структура

```text
hexa/lab/
  models.py       Неизменяемые снимки, Intent, Command, Result, GameAdapter
  modules.py      Четыре производителя намерений, без доступа к адаптеру
  engine.py       Единственная точка изменения: приоритеты, дедлайны, отмена
  simulator.py    Авторитетное состояние и проверка/исполнение команд
  server.py       Stdlib HTTP API, фиксированные 50-мс шаги, RLock
  ui/
    index.html    Четыре экрана интерфейса
    style.css     Адаптивное оформление, без CDN и сторонних ресурсов
    app.js        Визуализация, относительные запросы к API, локальные хоткеи

tests/test_lab.py  Детерминированные тесты ядра и регрессии конфигов
```

Пример команды — **не строка для последующего угадывания парсером**:

```python
Intent(
    source="combo", actor="hero", kind=Kind.CAST,
    priority=Priority.COMBO,
    due=now + 0.60, expires=now + 1.15,
    ability="emp", target="enemy-1", group="combo-1",
)
```

`WorldView` и вложенные представления — frozen dataclasses; словари наблюдения — read-only mapping proxies. Модуль возвращает намерение, но не меняет мир. Это архитектурный контракт доверенных встроенных модулей, **не security sandbox для произвольного стороннего Python-кода**.

Планировщик упорядочивает готовые команды по приоритету и времени; проверяет дедлайн, ручной перехват, резервирование и занятость исполнителя. Затем **сам адаптер** проверяет состояние и применяет приказ. `executed` означает подтверждённое применение приказа симулятором. Для движения это принятие и установка движения, а не достижение точки назначения.

### Почему это ещё не игровой адаптер

Синхронный `Result` достаточен для этого детерминированного симулятора. Для реальной асинхронной интеграции контракт нужно дополнить состояниями `sent / acknowledged / completed / timeout`, идентификаторами сессии, защитой от повторного исполнения, отменой на удалённой стороне и переподключением. Флаг возможностей не заменяет подтверждение реального режима игры.

Добавление адаптера к собственной кастомке потребует отдельного сквозного тестирования её API. Переносимость этого подхода в обычный матч из демонстрации не следует.

## API

- `GET /api/state` — мир, очередь, последние результаты, состояние модулей.
- `GET /api/export` — полный удерживаемый журнал команд (до 300) и событий (до 160), конфиг и состояние.
- `GET /api/health` — работоспособность, тип адаптера, явный `connected_to_dota: false`.
- `POST /api/control` — JSON-команды `combo`, `manual`, `move`, `damage`, `select`, `module`, `scenario`, `pause`, `speed`, `reset`, `import`, `clear_log`.

```bash
curl -X POST http://127.0.0.1:8080/api/control \
  -H 'Content-Type: application/json' \
  -d '{"action":"scenario","key":"priority"}'
```

Лимит тела — 32 КБ; некорректные типы, NaN/Infinity, неизвестные команды и координаты вне сцены отклоняются. CORS не открыт; cross-site POST блокируется. Это не полноценная аутентификация публичного сервиса.

## Конфигурация

По умолчанию настройки сохраняются атомарной заменой в `~/.hexa/lab.json`. Можно задать `--state-file`. Импорт проверяет конфигурацию перед применением. Сценарии меняют настройки текущей сессии и сами по себе не сохраняют их на диск. Последующее ручное изменение настроек сохраняет уже текущую конфигурацию.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Проверяются исполнение и сроки комбо, приоритеты, автоматическое лечение и перезарядка, ручная отмена, возврат фоновых задач, отдельное управление юнитами, дедлайны, отказ адаптера, выключение и падение модуля, неизменяемость наблюдения, сброс/пауза, конфигурация и четыре сценария.

Дополнительно исправлена ранее найденная проблема исходного `hexa/config.py`: поверхностные копии заменены на `deepcopy`, чтобы экземпляры конфигурации не разделяли изменяемые вложенные дефолты.

Исходный CLI сохранён: команды `modules`, `demo`, `gsi`, `serve` продолжают существовать. Новый режим — отдельная экспериментальная ветка исполнения, а не незаметная подмена старого.

### Дополнительная проверка интерфейса

В `tests/browser_smoke.py` сохранён браузерный smoke-test: четыре сценария, кнопки, хоткеи, настройки, импорт/экспорт, адаптивность и валидация HTTP. Для него отдельно нужен Playwright (приложению он не нужен). Запускайте против отдельного тестового экземпляра сервера: проверка сбрасывает арену и конфигурацию.

```bash
pip install playwright
python -m playwright install chromium
python tests/browser_smoke.py --url http://127.0.0.1:8080
```

На Linux могут понадобиться системные зависимости браузера: `python -m playwright install-deps chromium`. Скриншоты и JSON выгружаются во временную папку, либо в путь `--output`.

**Проверено при подготовке:** 40 unit/regression-тестов прошли на Python 3.13.14; четыре сценария прошли через интерфейс Chromium; проверены размеры 1440 и 390 px, импорт/экспорт и ввод; ошибок JavaScript и внешних сетевых запросов у страницы не было. Исходное CLI-демо также запускается: 23 уведомления, 0 ошибок модулей.

## Плагины

Lab умеет загружать внешние модули из каталога — идея заимствована из архитектурного
черновика «Гексагон», но с исправленным контрактом:

```bash
python -m hexa lab --plugins-dir examples/plugins
```

Готовый пример — `examples/plugins/rally.py` («Отход к точке сбора», P30): при здоровье
ниже порога уводит героя к точке сбора. По умолчанию выключен; включается на странице
«Модули», настройки переживают перезапуск и участвуют в импорте/экспорте конфига.

### Контракт плагина

- один или несколько классов-наследников `LabModule` (из `hexa.lab.modules`), определённых
  в самом файле; реимпорт чужих классов плагином не считается;
- атрибуты: `key` (уникальный), `title`, `description`, `priority` — целое 1–89, плагин не
  может встать выше автопредметов (P90) и ручного контроля игрока (P100), `requires` —
  набор `Kind`;
- `plan(world, selected)` возвращает список `Intent`. Прямого доступа к адаптеру и вводу
  нет: исполнением, приоритетами, резервированием и отменой управляет планировщик.

### Изоляция и ограничения

- файл с синтаксической ошибкой, конфликт ключа со встроенным модулем, плохой приоритет
  или падение конструктора — файл пропускается с записью в журнале, остальные работают;
- исключение в `plan()` отключает модуль, отменяет его команды и не роняет общий цикл
  (событие «Модуль изолирован»);
- песочницы нет: плагин исполняется с правами процесса — подключай только свой или
  прочитанный код;
- плагины работают с любым адаптером, но это по-прежнему полигон на симуляторе: сама по
  себе загрузка плагинов игровую интеграцию в Dota не добавляет.

Покрыто тестами (`tests/test_plugins.py`): обнаружение и порядок, игнор реимпортов,
отчёты о проблемах, участие в планировщике, ручной приоритет игрока, изоляция сбоев,
круговорот конфига.
